## 2. 原始问题与最终目标

用户在研究一个加密货币量化交易系统。近期核心问题来自 `atr_reclaim_0_35`：ATR reclaim 阈值 0.35 的 A/B 表现很好，但交易级归因显示改善可能主要来自路径依赖、满仓释放和少数 variant-only winners，而不是单变量质量稳定提升。

最终目标不是立刻部署某个参数，而是弄清：

- `atr_reclaim_0_35` 是否真的有可解释、可复现的策略价值；
- 满仓和旧仓长期占槽是否是系统性问题；
- 如果容量确实是问题，是否有证据支持 replacement 机制；
- 如果证据不足，应在哪一步停止，避免把 backtest 路径偶然误当成生产规则。

## 3. 背景与当前状态

此前 Codex 和 GPT 评审后形成了一条收紧后的 research roadmap：

`signal_fill_timing_audit -> blocked_entry_event_export -> replay_consistency_audit -> stale_slot_continuation_review -> blocked_candidate_vs_stale_slot_review -> shadow replacement experiment`

前五步都是诊断，不是部署依据。只有 Stage 3 和 Stage 4 都显示稳定、成本后仍存在 replacement edge，才允许设计 Stage 5 的完整状态机 shadow replacement experiment。

当前 Codex 已按该路线执行到 Stage 4，并得出结论：不进入 Stage 5。

## 5. 已做出的关键决策

1. `atr_reclaim_0_35` 暂停部署，降级为 `retest_path_dependent`。
2. 容量问题先做审计，不直接改 `max_active_positions`。
3. replacement 研究必须先验证 replay 时点和 blocked event 标签，再看 stale slot 和 candidate 的后续路径。
4. Stage 4 主样本只取 `candidate_rank=1` 的 blocked candidate。
5. V1 replacement eligibility 只允许 pre-TP1 stale slots，post-TP1 仅作对照。
6. replacement slot 主规则为同一 event 中“最老的 pre-TP1 且 `holding_bars >= 42` 的 active slot”。
7. oracle upper bound 只作为上限，不作为可执行策略。
8. Stage 4 若不能证明稳定 edge，则不进入 Stage 5。

## 7. Codex 当前最没把握的点

### 7.1 Stage 4 主规则是否过于朴素

不确定内容：使用“最老 pre-TP1 stale slot”作为 replacement slot 是否太粗糙。

为什么没把握：Stage 3 显示旧仓平均 continuation 弱，但 Stage 4 中被选中的 stale slot 经常是同一长期持仓，例如 APTUSDT，可能把“最老”规则变成对少数路径的过度重复抽样。

如果判断错误的影响：可能错误地否定 replacement 方向，或者相反，在另一个 slot selection 下发现更强 edge。

希望 GPT 检查：Stage 4 后直接停止是否合理，还是应先做一个预声明的替代 slot selection diagnostic。

### 7.2 R-normalized delta 是否足够

不确定内容：Stage 4 使用 `candidate_R - stale_slot_R`，每条腿按自身 per-unit risk 标准化。这是 path-quality diagnostic，不是完整组合 PnL。

为什么没把握：不同 trade 的 cash risk、持仓释放、后续机会链、手续费和滑点没有完整组合化。

如果判断错误的影响：可能低估或高估 replacement 对 portfolio equity curve 的实际影响。

希望 GPT 检查：在 Stage 4 结果弱的情况下，是否仍需要 Stage 5 shadow replay 才能最终判断，还是可按计划停止。

### 7.3 24/42/60 horizon 的解释

不确定内容：Stage 4 的 24-bar delta 为正且 positive ratio 超过 50%，但 42/60-bar median 和 positive ratio 转弱。

为什么没把握：这可能意味着 blocked candidate 短期更强但不能持续，也可能说明 42-bar horizon 不适合作为 replacement gate。

如果判断错误的影响：可能错过一个“短期换仓/短期释放”的机会，或误把短期噪音当 edge。

希望 GPT 检查：是否应围绕 shorter holding horizon 设计新问题，还是这已经属于新实验，不能用当前证据继续 replacement。

### 7.4 Oracle upper bound 明显为正的意义

不确定内容：Stage 4 oracle upper bound 的 R42 median 为正，但主规则和 lowest-unrealized sensitivity 不稳。

为什么没把握：oracle 说明事件中“事后看最差槽位”可替换会赚钱，但它不是可执行规则。

如果判断错误的影响：可能过早放弃容量方向，也可能被 oracle 诱导产生前视规则。

希望 GPT 检查：oracle 是否只应作为“未来可研究 slot selection”的线索，而不能推动 Stage 5。

### 7.5 下一步方向优先级

不确定内容：当前 replacement 分支收束后，下一步应该回到 `atr_reclaim_0_35`、研究 entry quality，还是扩展 Stage 4 到其他窗口。

为什么没把握：已有多个候选规则都处于 `retest` 或 `candidate_keep_review`，项目复杂度已有黑箱风险。

如果判断错误的影响：可能继续消耗时间在低收益分支，或过早切换导致没有解决核心策略问题。

希望 GPT 检查：从研究纪律角度，下一步最稳妥的工作是什么。

## 8. 当前完整方案与执行结果

### Stage 0：`signal_fill_timing_audit`

目标：确认 replay 的信号、决策、成交、同根 K 线处理顺序是否可审计。

主要发现：

- active exits 先于 WATCHING entries。
- WATCHING 按 `(-score, created_index, symbol)` 排序。
- capacity check 在 entry-zone touch、reclaim、sizing 之后。
- `step_trade` 可在同一次调用中让 WATCHING 入场并继续评估同根 stop/TP。

结论：`timing_audit_warn_same_bar_ambiguity`。

意义：可以继续，但后续 blocked event 必须显式记录 same-bar ambiguity。

### Stage 1：`blocked_entry_event_export`

目标：导出所有因 `max_active_positions` 被拒绝的 entry-ready candidates。

主要结果：

- source run：`110c51eef593`
- replay run：`ed682b4a5531`
- source/replay entered trades：`58 -> 58`
- blocked events：`512`
- same-bar entry-exit possible events：`0`
- same-bar entry-TP1 possible events：`2`

结论：`blocked_events_exported`。

意义：blocked event 样本可以被审计导出，但这不证明 replacement 有价值。

### Stage 2：`replay_consistency_audit`

目标：验证 source run 和 instrumented replay 的核心路径一致。

主要结果：

- source run：`110c51eef593`
- replay run：`1e3cbb13c14a`
- trades：`389 -> 389`
- entered trades：`58 -> 58`
- closed trades：`388 -> 388`
- active path mismatches：`0`
- open plan path mismatches：`0`
- final equity delta：`0`
- blocked event repeat：`512 -> 512`
- blocked event signature mismatches：`0`

结论：`replay_consistency_pass_with_ordering_limit`。

限制：候选排序不是 source run 原生持久化字段，只能通过源码排序 marker 和重复 blocked-event signatures 间接验证。

意义：可以继续做 stale slot 和 candidate comparison，但要记住 ordering evidence 是间接的。

### Stage 3：`stale_slot_continuation_review`

目标：独立评估 pre-TP1 仓位达到 42 bars 后继续持有的边际价值。

样本定义：已入场、达到 `42 bars = 168h` 时仍 pre-TP1 且未关闭的 active slots。

主要结果：

- source run：`110c51eef593`
- replay run：`8e24e6bda89b`
- total entered trades：`58`
- eligible pre-TP1 stale slots：`26`
- excluded TP1 before stale：`13`
- excluded closed before stale：`19`
- right censored：`1`
- `forward_R_24_mean=-0.282`
- `forward_R_42_mean=-0.132`
- `forward_R_60_mean=-0.191`
- `eventual_continuation_R_mean=-0.129`
- first-hit outcome：stop `15`，tp1 `10`，not_hit_by_end `1`

结论：`stale_slot_continuation_weak_retest`。

意义：旧仓继续占槽确实偏弱，支持继续做 replacement 诊断，但仍不支持部署。

### Stage 4：`blocked_candidate_vs_stale_slot_review`

目标：在真实 capacity-blocked event 中，比较 rank1 entry-ready candidate 与同一 event 中按事前规则选出的 stale slot。

主规则：

- candidate：`candidate_rank=1` 且 `block_reason=max_active_positions`。
- slot：同一 event 的 `active_snapshot_after_exits` 中，最老的 pre-TP1 且 `holding_bars >= 42` 的 active slot。
- post-TP1 slots 不进入 V1 eligibility。
- oracle 仅作 upper bound。

主要结果：

- source run：`110c51eef593`
- replay run：`e40da6f04438`
- total blocked events：`512`
- rank1 blocked events：`46`
- eligible comparison events：`42`
- rank1 without eligible stale slot：`4`
- same-bar stop possible events：`0`
- same-bar TP1 possible events：`1`
- right censored：`0`

主指标：

- `net_delta_R_24_mean=0.436`，median `0.145`，positive ratio `59.5%`
- `net_delta_R_42_mean=0.309`，median `-0.223`，positive ratio `42.9%`
- `net_delta_R_60_mean=0.176`，median `-0.432`，positive ratio `45.2%`
- `lowest_unrealized_slot_delta_R_42_mean=0.221`，median `-0.276`，positive ratio `35.7%`
- `oracle_upper_bound_delta_R_42_mean=0.756`，median `0.434`，positive ratio `78.6%`
- 20% trimmed mean R42：约 `0.001`
- first-hit pairs：`stop vs stop=27`，`stop vs tp1=6`，`tp1 vs stop=9`
- month leave-one-out：去掉 2025-07 后 mean R42 为 `-0.054`，说明 7 月对正均值有重要影响。

结论：`replacement_edge_not_supported`。

Codex 决策：

- 不进入 Stage 5 shadow replacement。
- 不部署 replacement。
- 不提高 `max_active_positions`。
- 不修改 `settings.toml`。
- 容量 replacement 分支暂时收束。

## 9. 方案制定依据

当前收束判断基于以下逻辑：

1. Stage 0-2 先确认数据链路、时点和 replay 一致性，避免用错误事件做 outcome 分析。
2. Stage 3 先单独看旧仓 continuation，证明“旧仓占槽可能是问题”，但这仍不能证明“新机会更好”。
3. Stage 4 再比较真实 blocked event 中的新机会和可替换旧仓。
4. 如果 Stage 4 主规则不稳定，不能用 oracle 或少数赢家推动进入完整换仓状态机。
5. 因为 Stage 4 的 R42 median 为负、positive ratio 低、trimmed mean 近似 0，所以不满足 Stage 5 gate。
