# GPT 方案评审包

## 1. 本轮希望 GPT 完成的任务

请评审一个加密货币模拟盘/候选扫描系统的“进场方案”。本轮不是要求重新设计整套交易系统，而是判断当前进场逻辑有哪些实质性缺陷、哪些地方值得优先改进、哪些改动需要先做离线验证再进入模拟盘。

请重点评估：

- 当前进场逻辑是否过度依赖短期正动量和支撑距离；
- MACD 目前只作为加分项是否合理，是否应成为硬门槛、反向过滤器或完全移除；
- `entry_reclaim_close_enabled` 这类 4h 收盘 reclaim 机制是否足够，是否需要引入额外确认；
- 两个已完成离线诊断试验的结果是否足以支持下一步实验方向；
- 在当前近期模拟盘表现较弱、大盘多日 `RISK_OFF` 的背景下，应该优先改进哪一环。

## 2. 原始问题与最终目标

用户的问题是：当前进场策略是什么样的，是否用到 MACD；随后希望把必要项目背景交给 GPT，讨论这个进场方案有哪些可以改进。

最终目标是：形成一个更稳健、可验证、不过度复杂的进场改进方向，用于后续离线回放、A/B 回测或模拟盘 checkpoint 决策，而不是直接凭主观判断改 live/paper 策略。

## 3. 背景与当前状态

这是一个加密货币算法交易项目，当前工作重点是模拟盘和离线诊断。系统扫描 Binance USDT 现货，生成交易候选；模拟盘只导入 `BUY_CANDIDATE`，然后用价格区间和 4h 收盘 reclaim 规则触发实际入场。

近期模拟盘情况偏弱：最近几天市场状态均为 `RISK_OFF`；已实现盈亏约 `-700 USDT`；当前仍有一个已进场仓位 `WLDUSDT`，未实现亏损相较前几日有所收窄；`ONDOUSDT` 仍是观察状态但价格低于此前止损参考，未出现 4h reclaim。模拟盘当前胜率和 TP1 命中率都不好，因此进场质量是核心问题之一。

最近一次代码工作不是直接改策略，而是准备 2026-07-16 的 paper checkpoint review：增加 checkpoint review 脚本、严格退出模式、终端摘要和 runbook。当前原则是 checkpoint 达到 `formal_audit_ready` 后，再决定是否把 shadow replay 候选规则推进到正式审计或模拟盘，而不是现在直接启用。

## 6. 已知事实、当前判断与待验证假设

### 已知事实

- 候选池：Binance USDT spot；24h quote volume >= 30,000,000；24h trades >= 30,000；最多分析 50 个；输出 top 5。
- 配置：`risk_reward_min = 2.0`，`risk_per_trade_pct = 0.01`，`min_history_days = 180`。
- 数据质量：`data_quality_filter_enabled = true`，`strict_data_quality_for_buy = true`；若 `BUY_CANDIDATE` 数据质量不是 `DATA_OK`，会降级为观察。
- 大盘过滤：`market_regime_filter_enabled = true`；当前配置 `risk_off_core_buy_enabled = false`，`RISK_OFF` 下买入候选会被降级。
- 扫描器计算：4h EMA20/50、1d EMA20/50、1h/4h RSI、4h ATR、4h MACD histogram、24h/3d/7d pct、成交量比、支撑距离、recent low/high。
- `BUY_CANDIDATE` 条件包括：score >= 35、4h 或 1d 趋势成立、24h 和 7d 动量为正、距离支撑 <= 4%、4h RSI <= 75。
- `WAIT_PULLBACK` 条件更宽：趋势和正动量成立、距离支撑 <= 10%、RSI 不过热，但不满足直接买入。
- MACD 当前只在 histogram > 0 时加 4 分；不是硬门槛，不参与最终模拟盘成交触发。
- 入场计划：根据支撑距离和 4h ATR 构造 `entry_low`/`entry_high`；止损取 recent low 下方或 ATR 下方；TP1 至少约 2R，TP2 至少约 3R。
- 模拟盘导入：只导入 `BUY_CANDIDATE`。
- 模拟盘触发：若 `entry_reclaim_close_enabled = true`，价格触及入口区但最近已收盘 4h close < `entry_high`，不进场，记录 `RECLAIM_PENDING`；等 4h close reclaim 后再由 `step_trade` 触发入场。

### 当前判断

- 当前策略不是 MACD 策略，而是 EMA 趋势 + 正动量 + 支撑距离 + RSI + regime + 数据质量 + 4h reclaim 的组合。
- 当前进场可能仍偏“追强势后的回踩”，因为要求 24h 和 7d 为正，同时又要求距离支撑不远。
- `entry_reclaim_close_enabled` 已经比单纯触及入场区更保守，但它不要求额外一根确认，也没有相对强度过滤。
- 在 `RISK_OFF` 连续多日时，策略即使扫描出机会也会被限制，近期模拟盘表现不能完全归因于进场条件本身。

### 待验证假设

- 增加 1 根 4h reclaim 确认能减少假突破/弱反弹进场，同时不会过多错过盈利交易。
- 增加相对强度过滤能更有效避免弱币反弹，但可能过度压缩交易数并错过赢家。
- MACD histogram 作为硬门槛可能减少弱动量入场，但也可能与 24h/7d 正动量重复，贡献有限。
- 当前 `distance_to_support <= 4%` 作为直接买入门槛是否过紧或过松，需要按币种波动率/ATR 标准化验证。
- 当前 TP/stop 基于 ATR 和 recent low/high，但入场确认没有用 ATR-normalized reclaim 强度，可能导致小幅 reclaim 也被接受。

## 7. Codex 当前最没把握的点

1. MACD 是否应该从“加分项”升级为“硬过滤”  
不确定内容：4h MACD histogram <= 0 时是否应禁止 `BUY_CANDIDATE`。  
没把握原因：当前已有 24h/7d 正动量和 EMA 趋势，MACD 可能重复；但模拟盘亏损显示弱反弹进场可能仍多。  
影响：若误升为硬门槛，可能降低交易数并错过早期反转；若不升，可能继续接入弱动量信号。  
希望 GPT 审视：MACD 更适合门槛、打分、背离/斜率条件，还是应保持辅助。

2. `entry_reclaim_close_enabled` 是否足够  
不确定内容：当前只要求最近 4h close >= `entry_high`，是否还需下一根确认、成交量确认、或 reclaim 后不再跌回区间。  
没把握原因：离线试验显示 1bar confirm 有过滤效果但会错过赢家。  
影响：过严会少交易、错过反转；过松会继续假 reclaim 进场。  
希望 GPT 审视：是否应将 confirm 作为 shadow replay 候选，而不是直接启用。

3. 相对强度过滤是否优先级高于 MACD  
不确定内容：是否应先用相对 BTC/ETH 或市场篮子的强弱来过滤弱币，而不是调 MACD。  
没把握原因：离线相对强度试验过滤更多亏损，但也错过更多赢家，样本仍偏小。  
影响：若优先级判断错，可能把系统改向过度保守或低样本过拟合。  
希望 GPT 审视：相对强度过滤是否适合作为 `BUY_CANDIDATE` 前置条件，还是作为评分/风险标记。

4. 当前正动量条件是否造成“买在反弹末端”  
不确定内容：24h > 0 且 7d > 0 是否使候选偏向已经涨过一段的币，和距离支撑过滤之间是否矛盾。  
没把握原因：它看起来合理，但可能在高波动币上筛到回撤前的强势末端。  
影响：若条件设计不当，会导致胜率低、TP1 命中率低。  
希望 GPT 审视：是否应改为“趋势强度 + 回踩质量 + reclaim 质量”，减少对短期涨跌幅的硬依赖。

5. 是否应该在 `RISK_OFF` 下完全暂停 alt 买入实验  
不确定内容：连续 `RISK_OFF` 时，是继续模拟盘收集样本，还是更严格限制新计划。  
没把握原因：模拟盘需要样本，但 risk-off 环境下样本可能主要验证防守能力，不代表普通市场。  
影响：暂停过多会样本不足；不停会扩大亏损和噪音。  
希望 GPT 审视：在研发阶段如何平衡样本收集与风险控制。

## 8. 当前完整方案

### 当前候选扫描流程

1. 从 Binance 读取 USDT 现货交易对。
2. 排除稳定币、杠杆类或配置中排除的 base asset。
3. 过滤 24h quote volume < 30,000,000 或 trades < 30,000 的交易对。
4. 先按流动性、24h 涨幅、异常振幅惩罚排序，最多分析 50 个。
5. 对每个币读取：
   - 1h K 线 168 根；
   - 4h K 线 120 根；
   - 1d K 线不少于 `min_history_days = 180`。
6. 若历史长度不足、ATR 无效、支撑位不可确定，则跳过。
7. 计算指标：
   - 4h EMA20/EMA50；
   - 1d EMA20/EMA50；
   - 1h RSI、4h RSI；
   - 4h ATR；
   - 4h MACD histogram；
   - 24h、3d、7d 涨跌幅；
   - 24h 成交量相对过去 6 天平均成交量；
   - 18 根 4h recent low；
   - 36 根 4h recent high；
   - 当前价格距离支撑的百分比。

### 当前评分逻辑

基础分来自 24h quote volume 的 log 值。然后：

- 24h 涨幅在限制范围内按权重加分；
- 7d 涨幅按权重加分；
- 3d 涨幅按较小权重加分；
- 若 `price > 4h EMA20 > 4h EMA50`，加 12 分；
- 若 `price > 1d EMA20` 且 `1d EMA20 >= 0.98 * 1d EMA50`，加 8 分；
- 4h RSI 在 48-70 加 8 分，70-78 加 3 分，>78 减 8 分，<35 减 4 分；
- 4h MACD histogram > 0 加 4 分；
- 成交量比在 0.8-3 之间加分，>5 减分；
- 距离支撑 <= 4% 加 6 分，>12% 减 10 分；
- 24h 高低振幅超过配置阈值减分；
- 24h 涨幅过大且距离支撑太远触发追涨惩罚；
- 24h 涨幅为负减分；
- 7d 涨幅为负减分；
- `RISK_OFF` 且不豁免时减分。

### 当前动作分类

`BUY_CANDIDATE` 条件：

- `score >= 35`；
- 4h 或 1d 趋势成立；
- `ticker.pct_24h > 0`；
- `pct_7d` 为空或 > 0；
- 距离支撑 <= 4%；
- 4h RSI 为空或 <= 75。

`WAIT_PULLBACK` 条件：

- 趋势成立；
- 24h 和 7d 动量为正；
- 距离支撑 <= 10%；
- RSI 不过热；
- 但未满足 `BUY_CANDIDATE` 的全部条件。

若 score < 20 则 `REJECT`；其他情况多为 `WATCH_ONLY`。如果大盘 regime 不允许买入，`BUY_CANDIDATE` 会降级为 `WATCH_ONLY`。

### 当前入场计划构造

根据当前价与支撑位距离：

- 距离支撑 <= 4%：入口区靠近支撑，`entry_low = support * 1.002`，`entry_high = min(price * 1.003, support + 0.7 * ATR)`；
- 距离支撑 <= 10%：等待回调，入口区在当前价下方；
- 距离支撑 > 10%：只等更深回调。

之后：

- `entry = (entry_low + entry_high) / 2`；
- `stop_loss = min(recent_low * 0.985, entry - 1.15 * ATR)`；
- `take_profit_1 = max(recent_high * 0.995, entry + risk * risk_reward_min)`；
- `take_profit_2 = max(entry + 3R, TP1 * 1.04)`；
- 若 RR 不达标，候选无效。

### 当前模拟盘导入和触发

- 只导入 `paper.import_actions = ["BUY_CANDIDATE"]`。
- 导入后状态是 `WATCHING`。
- 若 `entry_reclaim_close_enabled = true` 且当前价格 <= `entry_high`，系统读取最近已收盘 4h K 线。
- 如果最近 4h close < `entry_high`，则不入场，记录 `RECLAIM_PENDING`。
- 如果 4h close 已 reclaim，继续调用 `step_trade`；当当前价格位于 `entry_low` 至 `entry_high` 内时，触发 `ENTERED`。
- 入场后按止损、TP1、TP2 管理；当前还启用了 TP1 后 EMA20 trailing stop。

### 已完成但尚未启用的两个离线诊断试验

1. `entry_reclaim_confirm_1bar`
   - 样本：2026-06-19 至 2026-07-02，paper shadow replay。
   - opportunities 71，baseline_entries 61，variant_entries 36。
   - filtered_loser 11，missed_winner 3，improved_path 0，worse_path 0，delayed_entry 36，filtered_unknown 11，no_baseline_entry 10。
   - 当前结论：有用但不能直接启用；能过滤部分亏损，但会错过赢家，需要更多样本或 checkpoint 后再判断。

2. `relative_strength_gate`
   - 样本：2026-06-19 至 2026-07-02，paper shadow replay。
   - opportunities 71，baseline_entries 61，variant_entries 27。
   - filtered_loser 13，missed_winner 4，improved_path 0，worse_path 0，delayed_entry 0，kept_by_relative_strength 29，filtered_unknown 15，no_baseline_entry 5，data_gap 5。
   - 当前结论：更激进，过滤亏损更多，但压缩交易数更明显，也错过更多赢家。若二选一，目前 Codex 更倾向先继续验证 `entry_reclaim_confirm_1bar`，因为它更温和。

## 9. 方案制定依据

当前方案试图避免单指标策略，用多层过滤提高稳健性：

- EMA 判断结构趋势；
- RSI 防止明显过热；
- 支撑距离避免追高；
- ATR 构造风险收益和止损；
- 24h/7d 正动量避免逆势抄底；
- 数据质量过滤避免脏数据或映射错误；
- market regime 避免大盘风险环境下继续扩大买入；
- 4h reclaim 避免价格只是盘中刺入入口区后继续走弱。

取舍是：系统偏保守，但仍允许在强势币回踩支撑附近尝试入场。MACD 没被设为硬门槛，是为了避免与 EMA 趋势和 24h/7d 动量重复，也避免过早降低样本量。
